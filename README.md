# Carbon 呼吸紀錄

在家記錄狗狗的睡眠呼吸次數（SRR）、咳嗽、食慾、精神與活動，回診時給獸醫看的手機 Web App。
加到手機主畫面後像一般 App 一樣使用，沒有網路也能開。

> 這個 App 只是紀錄工具，不能取代獸醫師的判斷。

## 目前做到哪裡（v0.2.1）

| 功能 | 狀態 |
|---|---|
| 呼吸計數器（計時 30／60 秒、數 N 次、夜間介面、螢幕恆亮、震動） | ✅ |
| 狀態（熟睡／淺眠／清醒休息）、呼吸費力徵象、備註、不合理數值確認 | ✅ |
| 基準值、黃色／紅色警示、連續兩天偏高提醒、一鍵撥號 | ✅ |
| 每日紀錄（咳嗽、食慾、精神、活動、喝水、排尿、備註） | ✅ |
| 趨勢圖（呼吸次數可切換「只看熟睡／全部」、咳嗽；7／14／30 天）＋每筆紀錄清單、修改、刪除、手動補登 | ✅ |
| 設定（寵物資料、所有門檻、聯絡電話）、JSON 匯出／匯入（可合併兩支手機） | ✅ |
| 第一次使用的說明、免責說明 | ✅ |
| 回診報告：選一段期間 → 產生 PDF（摘要、趨勢圖、每日表格、個別紀錄與備註），可以分享、下載、列印 | ✅ |
| 體重紀錄與趨勢圖、用藥打卡 | 還沒做（資料格式已預留） |
| CSV 匯出 | 還沒做 |
| 兩支手機自動同步 | 之後視需要（資料格式已預留，見最後一節） |

## 部署：上傳 GitHub、接上 Vercel

第一次：

1. 把壓縮檔解開，會得到一個 `carbon-breath` 資料夾。
2. 到 GitHub 建一個新的 repository（名稱例如 `carbon-breath`，選 Private 也可以），**不要**勾選加入 README。
3. 在新 repo 的頁面點「uploading an existing file」，把 `carbon-breath` 資料夾**裡面的所有東西**（`src`、`public` 兩個資料夾，加上 `index.html`、`package.json`、`package-lock.json` 等檔案）全選、一起拖進去，按「Commit changes」。
   - 是拖「裡面的東西」，不是拖 `carbon-breath` 這個資料夾本身。上傳完之後，repo 第一層要直接看得到 `package.json`。
4. 到 Vercel →「Add New…」→「Project」→ Import 這個 repo。Framework Preset 會自動選 **Vite**，其他都不用改，按「Deploy」。
5. 一兩分鐘後會拿到網址（`xxx.vercel.app`），用手機開這個網址。

之後改版：把新版的檔案用同樣方式上傳到同一個 repo（同名檔案會被蓋掉），Vercel 會自動重新部署。
手機上開著 App 的人會看到「有新版本可用」的橫幅，按「立即更新」就換成新版；資料不會受影響。

## 加到手機主畫面

**iPhone（Safari）**

1. 用 Safari 開網址。
2. 點「分享」按鈕（方框加向上箭頭；新版 iOS 在「⋯」選單裡）→「加入主畫面」→「加入」。
3. 之後都從主畫面的圖示開啟。

> **請先加到主畫面，再開始記錄。** iPhone 上 Safari 分頁和主畫面 App 的資料是分開存的，在 Safari 裡記的紀錄不會出現在主畫面的 App 裡。（如果已經記了，可以在 Safari 裡到「設定 → 匯出備份檔」，再到主畫面的 App 裡匯入。）

**Android（Chrome）**

1. 用 Chrome 開網址。
2. 首頁會出現「安裝到主畫面」的按鈕；或點右上角「⋮」→「加到主畫面」／「安裝應用程式」。

## 測試離線

1. 有網路的狀態下，從主畫面開一次 App，等畫面出來。
2. 開飛航模式（Wi-Fi 也關掉）。
3. 把 App 整個關掉再重新打開：應該照常出現，可以量呼吸、填每日紀錄、看趨勢圖。
4. 關掉飛航模式。資料本來就只存在手機裡，不需要「上傳」。

## 資料格式

資料存在手機瀏覽器的 IndexedDB，資料庫名稱 `carbon-breath`，共 6 張表。
匯出的備份檔就是把這 6 張表原樣寫成 JSON：

```json
{
  "app": "carbon-breath",
  "formatVersion": 1,
  "exportedAt": "2026-10-02T15:00:00.000Z",
  "deviceId": "這支手機的代號",
  "data": {
    "breaths": [],
    "dailyLogs": [],
    "settings": [],
    "weights": [],
    "medications": [],
    "medLogs": []
  }
}
```

### 每一筆資料都有的欄位（為了同步預留）

| 欄位 | 說明 |
|---|---|
| `id` | 唯一代號。呼吸紀錄用 UUID；每日紀錄用日期（`2026-10-02`） |
| `createdAt` / `updatedAt` | 建立、最後修改時間（ISO 8601，UTC）。合併時以 `updatedAt` 較新的為準 |
| `deletedAt` | 平常是 `null`；刪除時填入時間。刪除只做標記、不真的移除，合併時對方才知道這筆被刪了 |
| `deviceId` | 是哪一支手機寫的 |

### `breaths`：呼吸紀錄

| 欄位 | 型別 | 說明 |
|---|---|---|
| `measuredAt` | 時間 | 測量時間（ISO 8601，UTC） |
| `date` | 文字 | 測量當下的當地日期 `YYYY-MM-DD`，「每天」的統計都用這個 |
| `rate` | 整數 | 每分鐘呼吸次數 |
| `mode` | `timed` / `quick` / `manual` | 計時模式／數 N 次／手動補登 |
| `breaths` | 整數或 null | 實際點了幾次 |
| `durationSec` | 數字或 null | 實際數了幾秒 |
| `state` | `deep` / `light` / `awake` | 熟睡／淺眠／清醒休息 |
| `signs` | 陣列 | 呼吸費力徵象：`openMouth` 休息時張嘴喘、`abdominal` 肚子用力呼吸、`sitting` 坐著不肯躺下、`gums` 牙齦發紫或發白 |
| `note` | 文字 | 備註 |
| `recorder` | 文字 | 記錄者（設定頁選填） |

警示燈號**不存在資料裡**，每次顯示時用目前的門檻現算（見下一節）。

### `dailyLogs`：每日紀錄（一天一筆）

| 欄位 | 說明 |
|---|---|
| `date` | 日期，同時也是 `id` |
| `cough` | `none` 0 次／`few` 1–3 次／`some` 4–10 次／`many` 10 次以上／`null` 沒填 |
| `coughContexts` | 陣列：`night` 晚上、`excited` 興奮時、`afterDrink` 喝水後、`other` 其他 |
| `appetite` | `normal` 正常／`reduced` 變少／`none` 不吃／`null` |
| `energy` | `normal` 正常／`low` 較差／`veryLow` 很差／`null` |
| `activities` | 用選的活動，陣列，例如 `["散步", "玩耍"]` |
| `activityNote` | 其他活動（自己打的文字），例如「上下樓梯」 |
| `recoveryMin` | 活動後喘多久才恢復（分鐘）；`0` 是沒有喘；`null` 沒填 |
| `water` / `urine` | `normal` 正常／`more` 變多／`less` 變少／`null` |
| `note` | 備註 |

### `settings`：設定（一個區塊一列）

每列是 `{ key, value, updatedAt, deviceId }`，沒存過的區塊用 `src/lib/defaults.ts` 的預設值。

| `key` | `value` 的內容 |
|---|---|
| `pet` | `name`、`breed`、`birthday` |
| `thresholds` | `yellowRate` 30、`redRate` 40、`baselinePct` 25、`baselineDays` 7、`baselineMinCount` 3 |
| `contacts` | `regular`、`emergency`，各有 `name`、`phone` |
| `counter` | `quickTarget`（數幾次模式的次數，預設 10） |
| `weight` | `baselineKg`、`gainAlertKg`（第二階段用） |

### `weights`、`medications`、`medLogs`

體重和用藥打卡第二階段才有畫面，格式已經定在 `src/lib/types.ts`，備份檔裡目前是空陣列。

### 只存在這支手機、不會跟著備份走的東西

記錄者名字、震動開關、外觀（深淺色）、上次用的計數方式、是否看過說明。這些存在 localStorage（`cb.` 開頭）。

## 計算規則

全部寫在 `src/lib/alerts.ts` 和 `src/lib/stats.ts`，`src/lib/rules.test.ts` 有對應的測試。

**呼吸數**
- 計時模式：次數 ÷ 秒數 × 60。
- 數 N 次模式：第一下點擊開始計時（不計入），之後點滿 N 次，N ÷ 經過秒數 × 60。
- 兩下間隔小於 0.12 秒視為誤觸，不計入。
- 結果低於 8 或高於 120 會先請使用者確認（`defaults.ts` 的 `PLAUSIBLE_MIN`／`PLAUSIBLE_MAX`）。
- 30 秒模式是「次數 × 2」，所以結果一定是偶數；想要更細可以用 60 秒或數 N 次。
- 數到一半畫面被切走（來電、切到別的 App）會直接作廢，請重新量。

**防誤觸**（數呼吸時眼睛是看著狗，不是看著螢幕）
- 數完之後先停在只顯示數字的畫面，中間怎麼點都沒有作用，要按最下面的按鈕才會進到填寫狀態的畫面。這樣時間到了手指多點的那幾下，不會誤勾到「呼吸費力徵象」。
- 每個畫面剛出現的前 0.6–0.8 秒不接受點擊。連點兩下「量呼吸」不會讓計時偷偷開始，連點兩下「儲存」不會跳過警示結果，連點兩下「刪除這筆紀錄」不會直接刪掉。

**手動補登的日期和時間**
- 年、月、日、時、分各一格，直接打數字就好：點進格子打的數字會蓋掉原本的，打滿了自動跳下一格。也可以按每一列右邊的按鈕，改用手機的日曆、時間選擇器。
- 時間一律是 **24 小時制**：半夜 12 點多填 0（例如 00:12），下午 2 點填 14。
- 格子下面會用白話再寫一次讓人確認，例如「會記成：今天（10/3 週六）凌晨 00:12」。
- 為什麼不用手機內建的日期時間欄位：那種欄位在手機上只能用選的；而且手機設成 12 小時制時，00:12 會顯示成「上午 12:12」，很容易看成中午。
- 不存在的日期（2 月 30 日）、未來的時間都不能存。打字的規則在 `src/lib/digitBox.ts`，日期的檢查在 `src/lib/dates.ts`。

**基準值**
- 首頁顯示的基準值：今天往前共 7 天，「熟睡」紀錄的中位數，至少 3 筆才顯示。
- 判斷某一筆紀錄時用的基準值：同樣 7 天內，但只算**比它更早量到**的熟睡紀錄（不含它自己，也不含之後才量的）。
- 注意：基準值會跟著最近 7 天移動。如果呼吸數是好幾天慢慢往上爬（例如從 21 升到 27 之後維持在 27），幾天後基準值也會變成 27，「比基準值高 25%」就不會再觸發。這種情況要靠固定的 30／40 門檻和趨勢圖來發現。

**單筆紀錄的警示**
- 紅色：熟睡呼吸數 ≥ 40，**或勾選了任何呼吸費力徵象**。
- 黃色：熟睡呼吸數 ≥ 30，或比基準值高出 25% 以上。
- 呼吸數的判斷只看「熟睡」的紀錄。呼吸費力徵象則不管當時是不是熟睡都算紅色（例如「坐著不肯躺下」本來就不會是熟睡）。
- 警示是用目前的門檻現算的，所以在設定頁調整門檻之後，過去的紀錄也會用新門檻重新判斷，首頁、清單和圖表上的門檻線會一致。

**連續兩天偏高（首頁提醒）**
- 連續兩個日曆天的熟睡呼吸中位數都達到黃色門檻。
- 今天已經有熟睡紀錄就看今天和昨天；今天還沒量就看昨天和前天。
- 「比基準值高 25%」用的是這兩天之前 7 天的基準值。
- 這兩天的紀錄前後至少要相隔 12 小時。半夜 23:50 量到偏高、照提示在 00:10 再量一次，日期上跨了兩天，但其實是同一個晚上，不算「連續兩天」。

**首頁燈號**
- 看過去 24 小時內最新的一筆「熟睡紀錄」或「有費力徵象的紀錄」：紅／黃／綠。
- 24 小時內沒有這樣的紀錄：灰色。
- 連續兩天偏高時至少是黃色。

**呼吸次數趨勢圖**
- 「只看熟睡」（預設）：每天一個點，是當天熟睡紀錄的中位數；細直線是當天最低到最高。
- 「全部」：再把淺眠、清醒休息時量的每一筆用空心的點畫上去（淺眠是圓形、清醒休息是菱形）。線、門檻線和基準值線仍然只算熟睡的紀錄，兩種數字不會混在一起算。
- 這個選擇只影響圖表和它的表格；下方的紀錄清單一直都列出全部紀錄，不是熟睡的會標「不列入」。

**咳嗽**
- 次數是選範圍，比較時換成代表值：0、1–3 → 2、4–10 → 7、10 次以上 → 12。
- 當天的值比「前 7 天有填的日子」的平均高，就提示「請同時留意睡眠呼吸次數」。

## 回診報告（PDF）

入口在「趨勢」頁右上角和首頁的「回診報告」。選 7／14／30 天或自訂期間（最多 120 天），App 會在手機上直接做出一份 A4 的 PDF，不需要網路。

**報告裡有什麼**（要改內容看 `src/lib/report.ts`，要改排版看 `src/lib/reportRender.ts`）

1. 標題、期間、製表日期、品種和年齡（設定頁有填才會出現）。
2. 摘要：熟睡紀錄筆數、期間中位數、最低／最高、基準值（算到報告最後一天為止）、紅色／黃色警示次數；咳嗽、食慾、精神各有幾天；另外寫出淺眠或清醒休息時量了幾筆。
3. 熟睡呼吸次數趨勢圖：每日中位數、當天最低到最高、黃色／紅色門檻線、基準值線。
4. 每日紀錄表：每天的熟睡中位數、最低–最高、筆數、警示次數、咳嗽、食慾、精神、活動後喘多久。連續 2 天以上完全沒有紀錄會合成一列。
5. 個別紀錄與備註：有警示的、不是熟睡時量的、勾了呼吸費力徵象的、有寫備註的紀錄，以及每日紀錄的備註和「其他活動」。

**數字怎麼算**
- 摘要、趨勢圖、每日表格的呼吸數字都只算「熟睡」的紀錄，跟 App 裡的規則一樣。
- 警示用**目前的門檻**現算（跟首頁、趨勢頁一致），門檻的數字會印在摘要下面。
- 已刪除的紀錄不會出現。

**怎麼拿到 PDF**

| 裝置 | 按鈕 | 之後 |
|---|---|---|
| iPhone | 「分享或儲存 PDF」 | 跳出分享選單：可以「儲存到檔案」、傳 LINE、AirDrop，或選「列印」 |
| Android | 「分享 PDF」／「下載 PDF」／「列印」 | 分享可以直接傳 LINE；下載會存到手機的「下載」資料夾 |
| 電腦 | 「下載 PDF」／「列印」 | |

畫面下方的預覽可以點一下放大看。

**為什麼不是「列印 → 另存 PDF」**：iPhone 從主畫面開啟的 App 叫不出列印畫面，所以改成 App 自己把每一頁畫出來（canvas），直接包成 PDF 檔，再交給分享選單。

**限制**
- PDF 的每一頁是一張圖，文字不能選取、不能搜尋（獸醫院列印或在螢幕上看都沒問題）。
- 字型用的是手機內建的中文字型，所以 iPhone 和 Android 做出來的字看起來會有一點不一樣。
- 體重和用藥還沒有做，所以報告裡沒有。

## 備份、換手機、合併兩支手機

- 設定 →「匯出備份檔」會產生 `carbon-breath-backup-日期.json`。手機上會跳出分享選單（可以存到「檔案」、傳 LINE、AirDrop），不支援分享的瀏覽器會直接下載。
- 設定 →「從備份檔匯入」是**合併**，不會蓋掉手機裡原有的紀錄：
  - 手機裡沒有的資料：新增。
  - 兩邊都有的呼吸紀錄：整筆以 `updatedAt` 比較新的為準（刪除也會跟著傳過去）。
  - 同一天的每日紀錄、同一個區塊的設定：以比較新的那邊為主，它沒填的欄位用另一邊的補上。例如一個人填了咳嗽、另一個人填了食慾，合併後兩個都在；一支手機填了急診電話、另一支改了醫院名稱，合併後兩個都留著。兩邊填了同一欄而且內容不同時，以比較新的為準。
  - 檔案裡格式不對的資料會略過，並顯示略過了幾筆。
- 兩個人各用一支手機記錄時：A 匯出 → 傳給 B → B 匯入，B 的手機就有兩邊完整的紀錄（基準值和警示也會用合併後的資料重算）。要讓 A 也完整，就反過來再做一次。
- 資料只存在手機裡。清除瀏覽器資料、刪掉主畫面的 App、換手機都會讓資料消失，**建議固定匯出備份**。

## 已知限制

- **iPhone 沒有震動回饋**：iPhone 的瀏覽器不提供震動功能，點擊時只有畫面回饋。
- **螢幕恆亮**：iPhone 從主畫面開啟時，需要 iOS 18.4 以上才有效；不支援時畫面會顯示提示。數呼吸時持續點擊，螢幕本來就不會自己變暗。
- **沒有推播通知**：瀏覽器不開著 App 就無法提醒，第一版不做。
- **蓋在畫面上的東西會吃掉點擊**：數呼吸時如果跳出來電橫幅或通知，那幾下可能沒算到。數字跟平常差很多時請重新量一次。
- **建議的系統版本**：iPhone iOS 16.4 以上；Android 用 2023 年之後版本的 Chrome。
- 咳嗽圖表的高度是「次數範圍」，不是精確次數。
- **回診報告的 PDF 不能選取文字**：每一頁是一張圖（原因見「回診報告」一節）。

## 技術選擇

- **Vite + React + TypeScript + Tailwind CSS + Dexie（IndexedDB）+ vite-plugin-pwa**，照原本規劃。
- **圖表沒有用 Recharts，改成直接畫 SVG**：只有幾張簡單的圖，自己畫可以完全控制夜間配色和標示方式，App 體積小很多（離線快取的檔案更少）。每張圖都可以切換成表格。
- **PDF 沒有用 jsPDF 之類的套件**：那些套件要顯示中文，得把一整套中文字型（好幾 MB）包進 App。現在的做法是用手機內建的字型把報告畫在 canvas 上，再用一個很小的程式（`src/lib/pdf.ts`，約 100 行）把圖片包成 PDF，App 幾乎沒有變大，離線也能用。
- **Service worker 由 vite-plugin-pwa 產生**，沒有用手寫的 `sw.js`：Vite 打包後的檔名每次都不一樣（帶雜湊值），要由打包工具自動列出要快取的檔案，離線才會完整。圖示、`manifest.json`、iOS 的 meta 標籤、「有新版本可用」橫幅都還是照 pwa-icon-setup 的做法。唯一不同的是圖示多做了「滿版」的版本給主畫面用：白底的圖示如果四個角是透明的，iPhone 會把透明的地方填成黑色，角落可能出現黑邊。
- **更新方式選「提示後才更新」**：新版下載好之後不會自己重新整理（怕數呼吸數到一半被打斷），要按「立即更新」才換版。
- **字型**：數字和英文用隨 App 打包的 M PLUS Rounded 1c（只含拉丁字元，約 66 KB，SIL Open Font License），中文用手機內建字型。

## 之後要讓兩支手機自動同步的話

現在的資料格式已經為同步做好準備（UUID、`updatedAt`、刪除只做標記、每日紀錄用日期當代號），加同步不需要重做資料。兩個都可以直接搭配 Vercel（由 App 直接連線，Vercel 那邊不用改設定）：

| | Dexie Cloud | Supabase |
|---|---|---|
| 做法 | 現在用的 Dexie 加一個同步外掛；兩支手機用同一個 email 登入（收一次性驗證碼） | 在 Supabase 開一個資料庫，App 自己依 `updatedAt` 上傳、下載 |
| 費用 | 免費方案含 3 個使用者，夠兩支手機用；付費是每 25 個使用者每月 3 美元 | 免費方案（500 MB）夠用；付費是每月 25 美元起 |
| 要注意 | 服務商規模較小 | 免費方案的專案一週沒有人使用會暫停，要到後台手動恢復（資料還在）；每天有在記錄就不會暫停 |
| 要改的程式 | 少 | 多（同步邏輯要自己寫） |

費用是 2026 年 10 月查到的，動手之前請再確認一次：
